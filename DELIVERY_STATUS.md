## Bus reinstatement scheduling guard — 22 October 2026

Inspection found that cancelling a bus trip released its scheduling slot, but restoring it did not recheck whether another trip had since reserved the bus or crew. Reinstatement now locks the bus and assigned users, requires current bus approval plus active crew membership/role, and rejects overlapping services before changing status. Existing status/version/owner authorization, incidents, audit and event notification behavior remains in place. Regression coverage cancels a trip, publishes an overlapping replacement, rejects reinstatement, rejects a revoked vehicle approval, then restores successfully after the conflict is removed. TypeScript checking and all five embedded PostgreSQL/PostGIS integration suites passed. Native PostgreSQL CI and deployment are pending; current hosted API and 0.6.0 APKs are unchanged. This is a bounded correction, not the full replacement-bus interface or production readiness.
